# Deployment & local development

Instructions for running Utasync on your machine and deploying the static build. For a product overview and feature list, see the [README](../README.md).

## Prerequisites

| Requirement | Notes |
|---|---|
| **Node.js 18+** | Required for Vite 8 and the build toolchain. |
| **npm** | Comes with Node; other package managers work if you prefer. |
| **Modern browser** | Chrome, Edge, or Safari recommended. WebGPU and sufficient RAM improve auto-align performance. |
| **Disk space** | ~300 MB+ for cached AI models (Whisper, embeddings) after first use; additional space for uploaded audio in the browser. |

Utasync is a client-only PWA. There is no backend server to run.

## Installation

```bash
git clone https://github.com/Ninjaruss/utasync.git
cd utasync
npm install
```

### Japanese tokenizer dictionary

Japanese tokenization uses [kuromoji](https://github.com/takuseno/kuromoji). Copy its dictionary into `public/dict` so the dev server and production build can serve it:

```bash
cp -r node_modules/kuromoji/dict public/dict
```

Re-run this after `npm install` if you remove `public/dict`.

### Vocal separation model (auto-downloaded)

On full-tier devices (WebGPU + 6 GB+ RAM), auto-align isolates vocals with Demucs before transcription **by default** — a stem sanity-check falls back to the raw mix if a separation comes back empty, so isolation can never make alignment worse. The model is a bespoke MDX-Net/Demucs ONNX with no npm package, provisioned one of three ways:

- **Automatic (default)** — `scripts/download-models.mjs` runs as a `prebuild` step (and during `npm run dev` setup), fetching `Kim_Vocal_2.onnx` (~64 MB) from a public UVR release into `public/models/`. No manual step; this is the path that runs on Vercel.
- **Ship your own** — place a file at `public/models/Kim_Vocal_2.onnx`; the download step verifies size and skips it if already present.
- **Fetch from a remote host at runtime** — host the ONNX anywhere CORS-enabled (must allow `GET` and `HEAD` from the app origin) and set at build time:

  ```
  VITE_DEMUCS_MODEL_URL=https://your-host.example.com/Kim_Vocal_2.onnx
  ```

  It downloads on first use and is cached by the service worker (Cache Storage, ~30-day retention).

If the model is unreachable, isolation is skipped and alignment still works on the transcription-only path (aligning on the raw mix). The app detects device tier and model availability automatically.

### AI models (automatic download)

Whisper (`Xenova/whisper-small`) and embedding models download from Hugging Face the first time auto-align or word alignment runs. They are cached in the browser (Cache Storage, ~30-day retention). A network connection is required for the initial download only.

## Environment variables

Utasync does not use `.env` files for runtime configuration. The app reads `import.meta.env.DEV` for development-only UI.

For production licensing, replace the placeholder LemonSqueezy public key in `src/payment/license.ts` with your store's ES256 public key before shipping.

## Run locally

```bash
npm run dev
```

Open the URL Vite prints (typically `http://localhost:5173`). The dev server includes middleware that serves kuromoji `.dat.gz` dictionary files as raw bytes (required for correct decompression in the browser).

## Build

```bash
npm run build
```

Output goes to `dist/`. Preview the production build locally:

```bash
npm run preview
```

## Deploy

Utasync builds to static files suitable for any static host (Vercel, Netlify, Cloudflare Pages, S3 + CDN, etc.).

1. Run `npm run build`.
2. Upload the contents of `dist/` to your host.
3. Ensure **`/dict/*.gz`** is served without automatic gzip re-encoding. Some static hosts treat `.gz` files as pre-compressed and set `Content-Encoding: gzip`, which breaks kuromoji loading. Serve them as `application/octet-stream` with no content encoding, or configure your host to disable double compression for `/dict/`.
4. Configure SPA fallback so unknown routes serve `index.html` (standard for Vite SPAs).
5. HTTPS is required for PWA install, OPFS, and service worker registration.
6. **Optional — faster auto-align (advanced):** Whisper can use a multi-thread WASM
   pool when the page is `crossOriginIsolated` (typically 2–4× faster transcription,
   same output — see `src/ai-pipeline/whisperPipeline.ts`). That requires
   `Cross-Origin-Opener-Policy: same-origin` and a COEP header on your host.
   **Do not enable COEP on the main app:** `Cross-Origin-Embedder-Policy`
   (including `credentialless`) breaks YouTube playback in Firefox and Zen
   (`NS_ERROR_DOM_COEP_FAILED`) and is unreliable in Safari. Utasync ships
   without these headers so YouTube streaming works everywhere; auto-align runs
   single-threaded by default.

The PWA manifest and Workbox service worker are generated by `vite-plugin-pwa`. ONNX models under `/models/` use cache-first runtime caching when present.

### Deploy to Vercel

The repo is Vercel-ready: `vercel.json` handles SPA fallback, the legal-page rewrites, and the (deliberately non-isolated) COOP/COEP headers, and `scripts/download-models.mjs` runs as a `prebuild` step so the ~64 MB vocal-separation model is fetched into `public/models/` during the build.

**Option A — Git integration (recommended).** Import the GitHub repo at [vercel.com/new](https://vercel.com/new). Vercel auto-detects Vite:

| Setting | Value (auto-detected) |
|---|---|
| Framework preset | Vite |
| Build command | `npm run build` |
| Output directory | `dist` |
| Install command | `npm install` (runs the `prepare` step: kuromoji dict + JMdict gloss) |

No environment variables are required. Optionally set `VITE_DEMUCS_MODEL_URL` to fetch the vocal model from your own CORS-enabled host instead of downloading it at build time. Every push to the production branch redeploys; pull requests get preview URLs.

**Option B — CLI.** `npm i -g vercel`, then `vercel` (preview) or `vercel --prod` (production) from the repo root.

**After the first deploy, verify on the live URL:**

- Japanese furigana renders on a song → confirms the kuromoji `/dict/*.gz` files are served as raw bytes (Vercel serves static files without extension-based `Content-Encoding`, so this normally just works — but it's the one host-specific risk).
- YouTube playback works → confirms the `unsafe-none` COOP/COEP headers took effect.
- A song aligns → confirms the Whisper weights load from the HuggingFace CDN at runtime (they are not bundled).

Note the `## Production checklist` above — in particular the LemonSqueezy public key in `src/payment/license.ts` if you use licensing.

### Production checklist

- [ ] `public/dict` populated (kuromoji)
- [ ] `public/models/Kim_Vocal_2.onnx` present — auto-downloaded by the `prebuild` step; only override if self-hosting the model
- [ ] LemonSqueezy public key updated in `src/payment/license.ts`
- [ ] HTTPS enabled
- [ ] Legal pages at `/privacy/` and `/terms/` served as static HTML (SPA fallback must not swallow these paths; see `vercel.json`)
- [ ] Dictionary gzip serving verified on your host

## Browser support

The baseline below is **measured, not asserted**. Run
`npx vite build && node scripts/bundle-syntax-floor.mjs` to re-derive it — the
script scans the emitted bundle for syntax and runtime APIs with known browser
floors and reports the highest. Re-run it after dependency bumps.

| Feature | Requirement |
|---|---|
| Core player & YouTube mode | **Chrome/Edge 98+, Safari 15.4+, Firefox 94+** |
| Local audio + OPFS | Chromium-based or Safari 17+ |
| Auto-align (Whisper) | WebGPU or WASM fallback; 4 GB+ RAM recommended |
| Vocal separation | WebGPU + 6 GB+ RAM; demucs model file |
| PWA install | HTTPS + service worker support |

Below the baseline the app does not degrade — it fails to parse and renders a
blank page. `build.target` in `vite.config.ts` is pinned to these versions so the
floor cannot drift upward silently when a dependency adopts newer syntax.

Note that `build.target` downlevels **syntax only**; it never polyfills runtime
APIs. The Safari 15.4 floor is set by `structuredClone` and `Object.hasOwn` inside
the transformers worker bundles, so lowering the target would produce a bundle
that parses and then throws — a worse promise than declining support.

## Troubleshooting

**YouTube won't play (Firefox / Zen, `NS_ERROR_DOM_COEP_FAILED`)** — the site must
not send strict `Cross-Origin-Embedder-Policy` headers (`credentialless` or
`require-corp`). This repo sets `unsafe-none` in `vercel.json` and the Vite dev
server. If you still see the error after updating:

1. **Hard refresh** (Ctrl+Shift+R / Cmd+Shift+R).
2. **Clear site data** for the origin (Settings → Privacy → Cookies and site data → search your URL → Remove), or in Zen: Site Information → Clear cookies and site data.
3. If you installed the PWA, reload once after updating — the app now auto-applies service-worker updates. If playback is still broken, unregister the service worker (devtools → Application → Service Workers) and clear site data once.
4. **Restart** `npm run dev` after pulling — an old dev-server process may still be serving cached COEP from memory.

Older builds precached `index.html` with COEP headers baked into the cached response; even after the server sent `unsafe-none`, Firefox/Zen could still load the stale document from the service worker. The precache no longer includes HTML (`cacheId: utasync-v3-no-coep`), and a one-time client purge drops older Workbox caches.

**Japanese readings or tokenization fail** — confirm `public/dict` exists and `/dict/` URLs return raw gzip bytes (see deploy notes above).

**Auto-align stuck on "Loading model"** — check network access for the first Hugging Face download; clear site data and retry if cache is corrupted.

**No vocal separation step** — isolation is default-on only on the **full** tier, so the device may be lite/manual (needs a WebGPU-capable browser with 6 GB+ RAM); the `Kim_Vocal_2.onnx` model may be unreachable (see the vocal-separation section); or the stem sanity-check rejected an empty separation and fell back to the raw mix (a `[stemQuality]` line is logged to the console when that happens).

**Storage warnings** — audio and models live in the browser; use Settings to review usage and remove songs if quota is low.
